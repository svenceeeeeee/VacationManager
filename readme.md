# Система "Vacation Manager" 
**Версия на изданието:** 1.0  
**Дата:** Ноември 2026 г.  

## 1. Общ преглед на проекта
"Vacation Manager" е цялостно десктоп приложение, предназначено да оптимизира администрирането на заявките за отпуск на служителите. Системата предоставя централизирана платформа за управление на потребителски роли, екипи, проекти и пълния жизнен цикъл на одобряване на отпуски.

## 2. Архитектура на системата
Приложението е изградено върху стандартна трислойна архитектура (3-Tier Architecture), за да се осигури разделяне на отговорностите, мащабируемост и лесна поддръжка:
* **Слой за представяне (Presentation Layer - `Forms`):** Графичен потребителски интерфейс, изграден с Windows Forms (WinForms).
* **Слой на бизнес логиката (Business Logic Layer - `VacationManager.Logic`):** Капсулира основните бизнес правила, процесите по валидация и оторизация (напр. `LeaveService`, `UserService`).
* **Слой за достъп до данни (Data Access Layer - `VacationManager.Data`):** Управлява свързаността с базата данни и изпълнението на SQL заявки (`DbHelper`).

## 3. Технически изисквания
За успешно компилиране и стартиране на приложението е необходима следната среда:
* **Работна рамка (Framework):** .NET / Windows Forms
* **Език за програмиране:** C#
* **Система за управление на бази данни (СУБД):** Microsoft SQL Server
* **Доставчик на данни:** `Microsoft.Data.SqlClient`
* **Среда за разработка (IDE):** Microsoft Visual Studio 2022

## 4. Конфигурация на базата данни
* **Име на базата данни:** `VacationManager`
* **Целеви сървър (Target Server):** `svence`

Низът за връзка (connection string) се управлява централизирано в слоя за достъп до данни. Уверете се, че името на сървъра съответства на вашата активна инстанция на SQL Server преди внедряване.

**Активен низ за връзка:**
public static string connectionString = @"Data Source=svence;Database=VacationManager;Trusted_Connection=True;TrustServerCertificate=True;";


## 5. Ръководство за внедряване и инсталация
1. **Разархивиране:** Разархивирайте предоставения архив на решението (solution) в локална директория.
2. **Инициализация на базата данни:** 
   * Отворете SQL Server Management Studio (SSMS).
   * Изпълнете предоставения SQL скрипт за внедряване, за да генерирате схемата на базата данни (таблици `Roles`, `Projects`, `Teams`, `Users`, `Vacations`) и да попълните първоначалните данни.
3. **Настройка на средата:**
   * Отворете `menijur_na_otpuski.sln` чрез Visual Studio 2022.
   * Проверете дали `connectionString` в слоя за достъп до данни отговаря на спецификациите на вашия сървър за бази данни.
4. **Компилиране:**
   * Кликнете с десния бутон върху проекта `Forms` в Solution Explorer и изберете **Set as Startup Project** (Задаване като стартиращ проект).
   * Компилирайте решението (Rebuild Solution).
5. **Изпълнение:** Стартирайте приложението.

## 7. Бележки по изданието (Версия 1.0)

### 7.1. Реализирани функционалности
* **Автентикация:** Сигурен механизъм за вход на потребителите.
* **Управление на потребители:** Пълни CRUD операции (Създаване, Четене, Обновяване, Изтриване) за потребителите на системата, включително възможности за търсене и филтриране.
* **Управление на отпуски:** Работен процес за подаване на различни видове отпуск (Платен, Неплатен, Болничен).
* **Валидация:** Строга валидация на времевите периоди, гарантираща логическа последователност (напр. крайната дата не може да предхожда началната).
* **Обработка на документи:** Задължително прикачване на файлове за заявки за болничен отпуск.
* **Работен процес за одобрение:** Мениджърски интерфейс за преглед, одобряване или отхвърляне на заявки за отпуск.
* **Локализация:** Пълна поддръжка на Unicode (кирилица), внедрена в схемата на базата данни (`NVARCHAR`) и бизнес логиката на приложението.

### 7.2. Известни ограничения
* **Извличане на документи:** Визуализацията на прикачени медицински документи от мениджърите изисква допълнителна конфигурация на файловата система в продукционна среда.
* **Оттегляне на заявки:** След като дадена заявка за отпуск премине в състояние "Одобрена" или "Отхвърлена", тя не може да бъде модифицирана или оттеглена от стандартния потребител.
